# Examples

Nine worked examples, one per question the engine is built to answer. Each directory
holds a `README.md` explaining what the example shows and a `command` script that is the
executable form of it.

## Two kinds of example, and the difference is enforced

**Offline examples** run from a clean checkout with no network access. They read the
documents under `fixtures/` - the generated corpus - and their exact stdout is committed
as `expected.out` beside them. `scripts/check-examples.sh` runs each one and diffs the
result byte for byte, so an example that stops working is a failing check rather than a
stale page.

**Endpoint examples** analyse something the engine can only learn by asking a network.
They cannot run in CI, and they do not pretend to. Their `command` script honours an
`AMASARIO_RPC` environment variable so the check can point it at an address that refuses
connections and require exit `69` - the `NETWORK` category. That verifies the one thing
that is verifiable without a chain: every flag in the documented command line exists and
parses, so a reader copying it gets a network failure rather than a usage error.

| Example | Shows | Needs a network |
| --- | --- | --- |
| [`local-contract/`](local-contract/) | Inspecting a contract on a local standalone chain | yes, a local node |
| [`testnet-contract/`](testnet-contract/) | Inspecting a contract on testnet | yes, testnet |
| [`verified-provenance/`](verified-provenance/) | A provenance chain that resolves end to end | yes, testnet |
| [`unknown-provenance/`](unknown-provenance/) | A chain that cannot be resolved, and what is reported instead | yes, testnet |
| [`direct-dependency/`](direct-dependency/) | Two observed invocations and the edges they establish | no |
| [`transitive-dependency/`](transitive-dependency/) | A direct invocation closed into a two-hop chain | no |
| [`impact-analysis/`](impact-analysis/) | The entities a change to one contract could reach | no |
| [`snapshot-diff/`](snapshot-diff/) | A state change between two observation boundaries | no |
| [`complete-analysis/`](complete-analysis/) | One subject rendered in all four output formats | no |

Every example is an analysis of the generated corpus under `fixtures/`, except the two
that inspect a live chain. The corpus documents are produced by the engine's own types
and regenerated by
`cargo run -p amasario-integration-tests --bin generate-fixtures`, which is why they can
be committed without becoming a claim about a network: they record what the engine
represents, not what a chain happened to contain.

## Running them

```console
# The offline examples, all of them, with the output compared to the committed bytes.
scripts/check-examples.sh

# One example, by hand, from the repository root.
bash examples/transitive-dependency/command
```

Every `command` script assumes the repository root as the working directory and uses
`cargo run -q -p amasario-cli --`, so a clean checkout is enough. An installed `amasario`
may be substituted for the `cargo run` prefix.
